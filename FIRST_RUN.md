# First assignment for the lead

Demonstrate whether a discrepancy originates in rule interpretation, FHIR binding, or execution. Use one development example from Criteria2SQL and report it on its own. Choose it using the criterion text and supported clinical concepts before accessing its reference query. Record the selection rule, dataset revision and split. Preserve the published test split for later evaluation.

1. Locate `pocketmd.py`. Read `QUICKSTART.md`, `criterion_workbench/README.md`, the latest local checkpoint and its receipts. Check the current CLI using `python3 pocketmd.py --help`. The saved archive includes `author`, `fhir-convert`, `fhir-screen`, `test` and `nih_benchmark/reconcile/combined_replay.py`. Check which rule format each entry point accepts before connecting them. If an existing result already answers the experiment, reuse it.
2. Prefer a criterion with nested AND/OR or an inclusive numeric boundary that the reference SQL can express. Construct source-linked synthetic controls that make rival interpretations produce different outputs. Supply a versioned concept map and unit assumptions. Prepare equivalent flat-table facts and FHIR resources for the same patient identifiers. Keep source data available to the verifier. Use complete positive and negative evidence for the cross-engine comparison. Use a separate missing-evidence control to check PocketMD abstention, since an SQL query can omit a patient for either false or unknown.
3. Give the rule author the criterion text, its available governing context and catalog only. Give the verifier the published SQL. Freeze the generated rule and results from (a) the rule on normalized test facts and (b) the same rule on the equivalent FHIR resources through the normal screening path. If the current system cannot run either step, record that boundary and implement the smallest general adapter required. An unresolvable protocol ambiguity is a valid authoring outcome.
4. After freezing, run the reference SQL on the complete rows and compare the resulting patient IDs. Inspect mismatches individually. If the normalized evaluation disagrees with SQL, review the criterion, generated logic, evaluator and reference interpretation. If normalized facts agree but FHIR differs, inspect the source-to-FHIR transformation, evidence binding, and matcher. Preserve an apparent reference defect for review. Never patch a case by patient, trial, or benchmark ID.
5. Verify one adjacent case with the same fix where available, replay affected historical controls, and record exactly what changed. For a change that touches the strict matching path, reproduce all 134 assignments with frozen predictions before scoring. If only synthetic tests change, report exactly that. A successful experiment produces a reusable test, cited source and rule, replayable receipt and either an identified defect or documented agreement.
